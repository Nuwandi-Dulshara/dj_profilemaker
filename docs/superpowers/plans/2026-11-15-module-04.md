# CV Templates Studio Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Deliver the Module 04 template gallery, twelve React layouts, saved templates, safe switching, customization, and shared exports.

**Architecture:** Extend the existing structured document engine and workspace Django services. Original templates are trusted design presets, while saved templates contain validated configuration only. Every CV opens in the existing editor and keeps its content and versions.

**Tech Stack:** React/TypeScript/Vite, Django REST Framework/PostgreSQL, TanStack Query, dnd-kit, docx, Chromium.

**Spec:** `modules/04-CV-Templates-Studio.md`; approved `docs/superpowers/specs/2026-11-14-studio-design.md`.

## Global Constraints
- All CVs, CV templates, and cover letters must be built, edited, and rendered using React.js.
- Use only free and open-source tools.
- Never remove working features without approval.
- Reuse existing authentication, document revisions, forms, projects, and exports.
- No executable user code in template configurations. Matching letters remain clearly planned until Module 05.
- Preserve pre-existing uncommitted files. No unrelated changes or commits of the user's work.

## Review Focus
- Duplicate creation retries must return the original project, scoped to the owner.
- Switching designs must preserve every content field and reject stale revisions.
- Private templates must not be enumerable or mutable by another user.
- Old documents and malformed design JSON must not crash the renderer.
- Long documents and all layout types must remain readable in PDF and DOCX; report layout differences honestly.

## Shared contract
- Extend CvDesign with optional/defaulted `templateId`, `layout` (`single`, `two-column`, `sidebar`), `textColor`, `lineHeight`, `sectionSpacing`, `headingStyle` (`line`, `plain`, `band`), `headerStyle` (`left`, `center`, `banner`), `headings` (section to string), `pageBreaks` (section keys).
- Template metadata: `id`, `name`, `description`, `categories`, `careers`, `layout`, `ats_risk` (`low`/`medium`), `ats_notes`, `design`, `favorite`, `last_used_at`, `is_custom`.
- GET `/templates/` filters: search, category, career, layout, ats_risk, favorite, recent, ordering; paginated count/results/next/previous. GET `/templates/:id/`; POST `/templates/:id/favorite/` with boolean favorite.
- GET/POST `/my-templates/`; GET/PATCH/DELETE `/my-templates/:uuid/`; POST `/my-templates/:uuid/duplicate/`. Custom detail may also resolve through `/templates/:id/`.
- POST `/projects/` with `kind: template_cv`, `template_id`, `title`, `import_profile` boolean, `idempotency_key` UUID creates document atomically and returns ProjectSerializer.
- POST `/projects/:uuid/switch-template/` with template_id and revision snapshots old design, preserves content, returns document payload.

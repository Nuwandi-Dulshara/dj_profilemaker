# Dashboard implementation plan

**Goal:** Replace the signed-in placeholder with the module 02 dashboard backed by PostgreSQL.
**Spec:** `modules/02-dashboard.md` and approved `docs/superpowers/specs/2026-11-14-studio-design.md`.
**Architecture:** Reuse session authentication and API client. Add a modular workspace backend (models, serializers, services, views), reusable modal and dashboard React components. No new dependencies.

## Scope and decisions

- Real owner-scoped projects, folders, document snapshots, activity, notifications and career profile summary. No seeded customer data.
- Counts include archived projects but exclude deleted projects; recent defaults exclude both. Search/pagination support active, archived and deleted views. Dashboard project list is reused at `/dashboard/projects`; it is a foundation, not completion of module 07.
- Real rename, duplicate (structured document snapshot), favorite, move-to-folder, archive and soft-delete actions. Deleted view supports restore. No destructive permanent deletion here.
- Seven-section career completion is derived from saved profile data. Storage reports stored document JSON bytes, includes archived/deleted documents, and is explicitly labeled; quota is nullable configuration.
- New Project modal lists the three workflows with honest unavailable states; no fake project creation, editors, export notifications, profile editor or full template gallery. Existing design explicitly defers these integrations.
- Retain current palette and minimum 14px secondary / 16px body type. Keyboard-accessible drawer, dialogs, notification and user dropdowns. Preserve home/auth/legal routes.

## API contract

- GET `/api/dashboard/summary/`: counts, profile sections/completed/total/percent, workflow availability.
- GET `/api/dashboard/recent-projects/`: paginated owner projects (search, state, page, page_size <= 50).
- GET `/api/dashboard/activity/`, `/api/dashboard/storage/`, `/api/notifications/`, `/api/folders/`.
- PATCH `/api/projects/<uuid>/`: title, favorite, archived, folder only.
- POST `/api/projects/<uuid>/duplicate/`, `/delete/`, `/restore/`.
- POST `/api/folders/`: name; PATCH `/api/notifications/<uuid>/`: is_read; POST `/api/notifications/read-all/`.
- All mutation responses confirmed before success messages; invalidate dashboard/project/activity/storage queries. Session auth and CSRF required throughout.

## Review focus

Cross-user UUIDs/folders; atomic actions and stale deleted records; errors not converted to zero counts; physical storage not misrepresented; no pretend editor/profile routes.

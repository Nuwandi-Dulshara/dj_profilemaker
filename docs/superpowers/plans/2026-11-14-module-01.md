# Authentication Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Real PostgreSQL-backed registration, session login/logout and password reset with shared sea-themed React pages.
**Architecture:** Django custom email user established before initial migration. CSRF-protected DRF endpoints; frontend session provider uses the shared API client, never browser token storage.
**Tech Stack:** Django 5.2 LTS, DRF, psycopg, React/TypeScript, TanStack Query, React Hook Form/Zod.
**Spec:** `modules/01-auth-pages.md`; approved studio design.

## Global Constraints

- Preserve home page and supplied sea image.
- Secure sessions, CSRF, backend password validation, rate limits and private data.
- Registration requires configured published Terms and Privacy links and explicit agreement; do not fabricate legal policies.
- PostgreSQL only. Do not access another application's database.

## Review Focus

- Case-insensitive duplicate email must fail without race-created duplicate accounts.
- Anonymous POSTs without CSRF fail, including login and registration.
- Session bootstrap errors must not be mistaken for unauthenticated success.
- Reset tokens expire, are single-use and do not reveal account existence.
- Registration remains unavailable until policy URLs/version are configured; development reset messaging never claims delivery.
